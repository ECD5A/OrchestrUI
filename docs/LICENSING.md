# Licensing and redistribution

Practical repository policy, not legal advice. Re-check upstream terms before release.

OrchestrUI original code/docs: MIT. It does not relicense third parties. Current researched boundaries: Kokonut UI OSS MIT (Pro separate); React Bits free MIT + Commons Clause (do not redistribute the component collection); daisyUI MIT; Bklit UI OSS MIT (premium separate); Anime.js MIT; Rive runtimes open source but `.riv` asset rights separate; Magic UI OSS/MCP MIT (Pro separate).

Never include paid/Pro components, templates, prompts, credentials, keys or authenticated registry output unless terms explicitly allow the exact redistribution. Prefer metadata + routing + official source links and install selected public components into the user's target app.

The live adapters read public registry indexes but retain and return only small metadata fields. Registry component source/files are neither stored nor redistributed. Fallback entries in `catalog/components.json` are original descriptions and identifiers/links needed for discovery, not copied component implementations.

React Bits is a special hard boundary: its current `LICENSE.md` permits use in applications/products while restricting selling, sublicensing or redistributing the components themselves. OrchestrUI must continue to point users to official upstream installation and must not publish a React Bits mirror, bundle or port.

Rive runtime packages and `.riv` artwork must be reviewed independently. A runtime's open-source license does not establish rights to a particular animation file.
